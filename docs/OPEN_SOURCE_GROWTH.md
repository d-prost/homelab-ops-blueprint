# Open Source Growth

The project should grow by usefulness, not by artificial activity.

## What to measure

Maintain evidence of genuine adoption:

- unique external contributors with merged pull requests;
- forks and repositories that reuse the patterns or tooling;
- issue reports from independent users;
- package or action dependents if reusable components are published later;
- release adoption and downstream references;
- OpenSSF Scorecard and criticality signals when the project is large enough to make them meaningful.

## How to encourage real contributions

- keep `good first issue` tasks small and useful;
- document architecture before asking contributors to infer it from Ansible;
- accept new stateless stack examples when they demonstrate a reusable pattern;
- publish stable releases instead of expecting users to track `main`;
- answer reproducible bug reports with enough detail that later users can learn from them;
- avoid adding abstractions until at least two real use cases require them.

## Maintainer evidence

For grants, open-source programs, or sponsorship applications, use verifiable public evidence from GitHub, registries, OpenSSF, and release history. Do not claim thresholds that the project has not reached.
